# 对接中转

让客户端先连中转，再到节点，用来改善线路（例如国内前置 → IX → 海外落地）。节点可以是面板搭建的入站，也可以是 [导入的节点](./import.md)。

## 添加中转线路

**中转** 页的 **线路** 标签按节点列出所有中转线路，点一个节点 → 选择隧道即可添加（也可以在节点页点入站 → **中转**）。隧道在 **中转** 页的 **隧道** 标签创建，入口是中转机；底层的转发规则在 **规则** 标签，见 [转发规则与用户](./forward.md)。

选好隧道后，可以直接设置 **入口监听 IP** 和 **连接落地地址**。入口服务器有 IPv6、落地有 IPv4 时，点 **IPv6 入站 → IPv4 落地** 即可一键配置，随后点 **创建中转**，无需再到规则页修改。

已有线路在 **管理 → 编辑** 中也可以修改相同的地址设置。线路卡片分别显示入口和出口目标的 IP 类型、地址与端口，方便区分 IPv4 和 IPv6 线路。

- **入口监听 IP**：客户端连接的地址；分享地址留空时，分享链接和订阅自动使用所选入口 IP。自定义域名仍可填在 **分享地址** 中
- **连接落地地址**：中转机或隧道出口连接落地时使用 IPv4、IPv6 或自动选择；只影响这一条中转，落地需要监听对应地址
- 指定入口监听 IP 适用于单入口的面板转发或 realm 隧道；多入口和 nftables 使用默认入口配置。IPv6 入站转发到 IPv4 落地时，中转机（隧道转发时为最终出口）仍需具备 IPv4 出网能力

## 对接方式

- **端口转发**：中转机直接把流量转发到落地机的公网地址
- **隧道转发（出口为落地机）**：流量经隧道到落地机，再转发到 `127.0.0.1:入站端口`。入站可以只监听 `127.0.0.1`，落地机不对外暴露端口
- **隧道转发（出口为其他服务器）**：用于“前置 → IX → 落地”这类多跳线路。流量经隧道到出口服务器（如 IX），再由出口服务器连接落地机的公网地址。只需要中转、不需要加密时，隧道协议选 TCP 即可

## 前置 → IX → 落地

1. 服务器页添加前置、IX、落地三台机器，都装好 agent
2. 隧道页新建一条“隧道转发”：入口选前置，出口选 IX，协议按需选择（不需要加密就选 TCP）
3. 点击落地机上的入站 → **中转**，选这条隧道
4. 如果 IX 只允许前置访问，在 IX 的防火墙里放行前置的地址即可；落地机可以开启入站白名单，只放行 IX

订阅里的中转线路使用前置的地址和入口端口。

## 订阅与清理

中转线路会自动加入订阅，名称为“隧道名 → 入站名”。删除中转、入站或内核时，相关的转发会一并清理。

若想避免同一个节点同时显示直连和中转，在节点组的 **处理 → 筛选 → 线路** 选择 **有中转优先显示中转**。同一节点有启用的中转时只显示全部中转线路，没有中转时保留直连。选项按订阅独立保存，不改变其他订阅、入站监听或防火墙。

中转停用或删除后，若该节点没有其他启用的中转，下次生成订阅时恢复直连；入站设置了“仅通过中转提供”或仅监听本机时，仍不会提供直连。中转存在与否在名称、地区等其他筛选前判断；测速失败或入口暂时离线不会自动暴露原始直连。

## 获取真实客户端 IP（仅 Xray）

开启后，中转转发会附带 PROXY protocol，落地机内核日志里能看到客户端真实 IP。开启后直连将无法使用，入站会自动变为“仅中转”。

## 入站白名单

开启后，该入站端口只放行本机、直接连接落地机的服务器（端口转发的中转机、隧道转发的出口服务器）和你填写的额外 IP / 网段，其余来源直接丢弃，只影响这一个端口。中转增删时白名单会自动更新。

## 延迟

**中转 → 线路** 里每条中转线路后面显示 **经这条线路到各测试点的延迟**，估算方法是：

> 入口（前置）到测试点的延迟 + 入口 → 各跳 → 出口 → 落地 每一段的延迟

- 每段都是服务器 agent 测的 TCP 连接延迟，每 3 分钟测一次；[服务器到延迟测试点](./latency.md) 的采集独立每 1 分钟运行。点延迟可以看到每个测试点的估算值和每一段的延迟，点 **重测** 或上方 **测延迟** 马上测
- 入口要设置 [延迟测试点](./latency.md) 才有“到测试点”的部分；没设置时只显示入口到落地的路径延迟
- 多跳线路（前置 → IX → 落地）按隧道里每组的第一个服务器算；有多个入口时按第一个入口算
- 任一段不通时显示“线路不通”，详情里能看到是哪一段
- 共享（其他面板）的服务器和离线的服务器不检测
- 只是估算：实际延迟还和隧道加密、服务器负载有关，测的是 TCP 连接延迟，不代表 UDP

中转的 **管理中转** 对话框里也能看到每条线路的延迟。
