# 延迟与回程

面板可以让每台服务器定时测到国内各地运营商的延迟和丢包，并检测回程走的是哪条线路（CN2 GIA、163、9929、4837、10099、CTGNet、CMI、CMIN2 等），结果显示在服务器列表和卡片上。

## 原理

- **延迟**：服务器每 1 分钟向每个 **测试点** 发 4 次 TCP 连接，记录平均延迟和丢包。测试点是放在各地运营商机房里的地址，所以测出来的就是“该地区这家运营商的用户到服务器”的延迟，比从面板服务器测准确得多
- **回程**：服务器对每个测试点做一次路由追踪，按经过的骨干网判断线路，每天自动检测一次

不设置测试点时，服务器不测延迟；导入的节点在节点页显示面板服务器到它的延迟，只能作为参考。

同一台服务器最多同时执行 8 个 TCP 探测，其余自动排队。排队和执行共用超时预算，过期任务会停止；队列已满、排队超时、服务器离线和测试点连接失败会分别显示原因。只升级面板也能用；agent 一起升级后，面板已放弃的探测在服务器上也会停止。

经中转的线路（前置 → IX → 落地）也有估算的端到端延迟，见 [对接中转 - 延迟](./relay.md#延迟)。

## 设置测试点

**设置 → 延迟测试点**：

1. 点 **添加三网推荐** 一键加上广东电信、上海联通、北京移动；或点 **添加预设** 从北京 / 上海 / 广东 × 电信 / 联通 / 移动里挑；也可以 **自定义** 任意域名或 IP 和端口
2. **默认**：打开的测试点所有服务器都测（单独设置过的服务器除外）
3. **卡片显示**：最多勾 3 个，卡片上固定显示它们；一个都不勾时显示最差和最好的
4. 保存后所有服务器马上重测一遍

最多 30 个测试点。改名会自动同步到单独设置过的服务器。

## 给服务器单独设置

不同服务器面向的用户不一样（比如有的只卖移动），可以给服务器单独选测试点：

- **单个**：**服务器** 页点服务器的 **测试点**
- **批量**：**服务器** 页点 **多选**，勾选服务器后点 **测试点**，保存会覆盖这些服务器原来的设置

选 **跟随默认** 就测 **设置** 里打开“默认”的测试点，那边改了这里跟着变；选 **自定义** 自己勾选，也可以指定这台服务器卡片上固定显示哪几个。一个都不勾就是这台服务器不测延迟和回程，卡片上显示“不测延迟”。

## 看结果

延迟和回程显示在 **服务器** 页的服务器列表和卡片上；**节点** 页只给导入的节点显示面板测的延迟，自建入站只显示能不能连上（线路看它所在的服务器）：

| 颜色 | 含义 |
|------|------|
| 绿 | 低于 100 ms，没有丢包 |
| 黄 | 100–300 ms，或有丢包 |
| 红 | 300 ms 以上、丢包 50% 以上，或连不上 |

每个测试点下面一行是它的回程线路。点延迟打开 **延迟详情**，列出到每个测试点的延迟、丢包和回程，底部有四个按钮：

- **重测**：马上测一次
- **趋势**：延迟趋势图
- **回程**：回程路由详情
- **测试点**：给这台服务器单独选测试点

卡片上方“1 分钟前”指延迟检测时间；线路的识别时间在 **延迟详情** 和 **回程** 中单独显示。临时检测失败时保留上次有效线路，并在标签旁标记 **上次**，详情会说明最新检测的失败原因。尚未检测或没有可识别的线路时，卡片显示 **回程待检测** / **回程未识别**。

## 延迟趋势

点 **趋势**，可以看最近 1 小时、6 小时、24 小时、7 天或 30 天里到每个测试点的延迟曲线，以及分位数和异常摘要，适合看晚高峰是否拥堵。

实际采集周期为 1 分钟，页面每 60 秒自动刷新。**数据粒度** 的“1 分钟 / 5 分钟”只控制已有采样的汇总方式；“默认”会按时间范围自动合并采样。网络质量采集独立运行，一轮完成后才会开始下一轮，超时或排队可能使实际完成时间略有波动。

历史数据按 **设置 → 服务器与监控 → 监控数据保留天数** 自动清理。

## 回程线路

点 **回程** 查看到每个测试点经过的每一跳和识别出的线路，点 **重新检测** 马上测一次。新版 agent 优先向测试点配置的端口发送 TCP SYN 探测，路径不完整时再补充 ICMP；面板分别识别两条路径，优先采用能识别线路的结果，两者都识别成功时保留 TCP 结果。不同协议的跳点不会拼成一条路径。

IPv4 和 IPv6 都会查询每一跳的 ASN（网络归属），查询暂时失败时使用已知骨干网段兜底：

| 线路 | 依据 |
|------|------|
| 电信 CN2 GIA / GT | AS4809 / 59.43；同时出现 202.97 骨干、或 CN2 前出现电信 AS4134 时推断 GT，否则推断 GIA |
| 电信 CTGNet | AS23764，或已知 CTGNet 骨干网段 |
| 电信 163 | AS4134 / 202.97 |
| 联通 9929 | AS9929，或 218.105 / 210.51 / 210.14 / 210.78 |
| 联通 4837 | AS4837 / 219.158 |
| 联通 10099 | AS10099；随后进入 9929 / 4837 时显示组合线路，例如“联通 10099 → 9929” |
| 移动 CMIN2 | AS58807；ASN 查询失败时可用已知 CMIN2 IPv6 网段兜底 |
| 移动 CMI | AS58453，或 223.118–223.121 等已知 CMI 网段 |
| 移动 9808 | AS9808 / 221.183 / 111.24；仅看到移动国内骨干时单独显示，不据此认定 CMI 或 CMIN2 |
| CERNET / CERNET2 / CSTNET | AS4538 / AS23910、AS23911 / AS7497 |

跨运营商路径按经过顺序显示，例如“移动 CMI → 联通 4837”。展开详情可查看探测协议、每跳 ASN 和识别说明。隐藏跳点可能影响判断，CN2 GIA / GT 等名称是本次路径特征的推断，不能代替线路产品承诺。

有效识别结果会保存在数据库中，每台服务器仅保留一份最新快照，面板重启或升级后自动恢复。新的检测失败、未识别，或 ASN 查询不完整导致线路结论变化时，保留上次的线路及其原始识别时间；详情中的跳点仍是最新一次探测的结果。修改测试点地址、端口或更换服务器后，不会沿用旧目标的线路。

IPv4 和 IPv6 线路独立展示：即使 IPv4 未识别，也能显示已识别的 **v6** 线路。两者线路相同且状态相同时合并显示；只有一条使用上次结果时，分别标记。

- **升级**：TCP 探测需要更新后的 agent；旧 agent 仍使用 ICMP，面板也能用新的 ASN 规则识别旧 agent 返回的跳点
- 双栈服务器对有 IPv6 地址的测试点两条都测：回程详情里每个测试点分 IPv4、IPv6 两行，卡片上显示 IPv4 线路，IPv6 走得不一样时后面多一个小标签；IPv6 线路变化也会提醒。双栈检测需要 agent 3.3.28 及以上
- 服务器没有 IPv4、或测试点只有 IPv6 地址时自动改用 IPv6 检测，结果旁标 **IPv6**；只有 IPv6 的服务器要选有 IPv6 地址的测试点。IPv6 回程需要 agent 3.3.27 及以上
- 回程每天自动检测一次，失败、未识别或 ASN 查询不完整的 6 小时后重试；测试点地址、TCP 端口变更或 agent 升级后会重新检测
- 需要服务器以 root 运行（或有 NET_RAW 权限），见 [升级](./upgrade.md#agent-升级)
- 未确认到达目标时只显示到最后一个有回应的路由器；未收到公网回应、ASN 查询暂无结果、未发现可确认骨干网，会在详情里分别说明原因。不会根据测试点名称猜测线路

## 告警

在 [通知](./notify.md) 里勾选：

- **延迟 / 丢包异常**：某个测试点连续 3 次（约 3 分钟）丢包超过阈值（默认 20%），或延迟超过阈值（可选，默认不按延迟提醒），恢复时也会通知
- **回程线路变化**：每天检测回程时对比上一次，例如 CN2 GIA 变成 163

## 连通性检测

和测试点无关，面板服务器每 3 分钟会连一次节点页上的所有节点，包括导入的节点和面板搭建的入站，看端口能不能连上。节点页上方 **更多 → 检测节点连通性** 可以马上测一遍：

- 连得上：自建入站显示“可连接”，导入的节点显示面板到它的延迟
- 连不上：红点，并显示原因（连接超时、域名解析失败、无法连接）

面板搭建的入站按 **分享地址** 检测，没填分享地址时用所在服务器的 IP。内核在跑但连不上，通常是云服务商的安全组或防火墙没有放行这个端口。服务器离线或内核没在运行时不检测，只显示服务器或内核的状态（这两种情况本来就有各自的提醒）。

检测是从 **面板服务器** 发起的 TCP 连接，只能作为参考：面板连不上不代表中转机或客户端也连不上，反之亦然。以下几种不检测，不显示状态：

- Hysteria2、TUIC：只用 UDP，无法这样检测
- 开启了“仅允许中转机访问（防火墙白名单）”的入站：面板服务器不在白名单里，必然连不上
- 只监听本机（127.0.0.1）的入站

面板服务器没有 IPv6 时（常见于 Docker 部署），连不了只有 IPv6 的节点。这种情况不算连不上，也不发提醒：面板搭建的入站改由所在服务器自己连一下这个地址和端口，显示“服务器自检（面板没有 IPv6）”；服务器自检只能确认内核在这个地址上监听，确认不了云服务商的防火墙有没有放行。导入的节点没有 agent，这种情况下不检测。

开启 [通知](./notify.md) 后，节点连续两次连不上会推送提醒。
